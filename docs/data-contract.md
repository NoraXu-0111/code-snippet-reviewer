# Data and API contracts

See [design](design.md) for architecture and decisions. FastAPI `/openapi.json` is the field-level contract; `src/shared/api-types.ts` is generated by `npm run api:types`.

## Conventions and entities

IDs are UUIDs; timestamps are UTC ISO 8601. JSON uses camelCase and SQL uses snake_case. Source ranges are one-based and inclusive. Code is stored without trimming or rewriting line endings.

| Entity | Core fields and ownership |
| --- | --- |
| Snippet | id, title, language, code, createdAt |
| ReviewRun | id, snippetId, model, status, createdAt, startedAt, finishedAt, error |
| Finding | id, reviewRunId, startLine, endLine, severity, category, description, suggestedFix, resolution |
| DiscussionConversation | id, findingId, createdAt |
| DiscussionTurn | id, findingId, conversationId, clientRequestId, userMessage, assistantMessage, model, status, attempt, timestamps, error |

Limits: title 1–120 characters, language 1–50, nonblank code up to 100,000 Unicode code points, nonblank question up to 4,000. Unknown languages remain valid and render as plain text. Severity is `critical | warning | info`; category is `bug | style | performance | security`. An omitted suggested fix normalizes to null.

## Review and finding state

| Execution status | startedAt | finishedAt | error |
| --- | --- | --- | --- |
| queued | null | null | null |
| running | required | null | null |
| succeeded | required | required | null |
| failed | optional | required | nonblank |

Transitions: `queued -> running -> succeeded/failed`, or `queued -> failed` before execution. Terminal review runs are immutable execution records; an intentional retry creates a new run. Findings may still change resolution independently: `open | accepted | dismissed`. Reopening sets `open`; repeated resolution writes are idempotent, with last-write-wins across clients.

Dashboard status derives only from the newest review (`created_at DESC, rowid DESC`): no run = `not_reviewed`, queued/running = `in_progress`, succeeded = `reviewed`, failed = `failed`. Language/status filters combine with AND semantics. History preserves each run's findings and resolutions.

LLM output is `{ findings: [...] }`. Validate the whole result and source bounds before atomically saving findings and successful status. A successful empty array is valid. Review detail reads run and findings from one SQLite snapshot.

`006_review_submissions.sql` maps unique `(snippet_id, client_request_id)` to a run in the creation transaction. Replays return the same run at any status, including after restart without provider configuration. Existing runs are preserved. New submissions need a configured provider; a different submission while a review is active returns 409. The browser persists its UUID before POST and retains it until confirmation; clearing storage removes recovery identity.

## Per-finding AI conversation

A finding owns multiple conversations; each turn belongs to exactly one. Migration 005 assigns legacy turns to an original conversation whose ID equals the finding ID, preserving existing messages, IDs, attempts, and timestamps. Composite foreign keys enforce conversation/finding ownership.

Creating an empty conversation makes no model call. Its client UUID is also its conversation ID and idempotency key. Creation is blocked while that finding has an active reply; replay of an existing creation remains available. Conversation selection, drafts, and uncertain submissions are stored separately in browser session storage.

Turn invariants:

- Unique `(finding_id, client_request_id)` identifies a submission. Identical question/conversation replay returns the existing turn; changing either returns 409.
- At most one queued/running reply per finding, across all its conversations. Review and reply execution share two provider slots and a timeout that includes queue wait.
- Successful turns have a nonblank assistant message. Queued/running/failed turns have no answer. Review timestamp/error rules also apply.
- Context includes source/language, the finding, and up to ten recent successful exchanges from the selected conversation, in order, followed by the new question. Failed exchanges are excluded; all saved history remains visible.
- Only the latest failed turn within the selected conversation can retry in place. The client supplies its current attempt; retry increments it, and completion writes must match it. Another active reply blocks retry.
- Restart marks unfinished turns failed while retaining questions/history. New reviews create new findings and do not copy or match conversations.

## Model selection

`GET /api/models` returns `{provider: "openai", defaultModel, models: [{id, name}]}` without using the provider key. The curated catalog includes GPT-4.1 mini, GPT-4.1, GPT-4.1 nano, plus an operator-configured default if different. The app default comes from `OPENAI_MODEL`; a browser-local preference selects defaults for new UI requests.

Review and question POST bodies accept optional `model`. Omitting it on a new request resolves/persists the current app default. Unsupported choices return 400 without creating a job. An explicit model that differs on an existing request UUID returns 409; omission on replay recovers the original job even if defaults changed. Reply retries retain the persisted model. If a previously configured model is removed from the catalog, retry fails explicitly rather than silently switching models; existing results/replays remain readable.

Migration 007 adds nullable `model` to review runs and discussion turns, backfilling only from matching trace subjects (and turn attempts). Unknown historical models stay null. A retry of an unknown legacy reply records the current default for its new attempt. Provider adapters have separate model settings, so request choices do not mutate global configuration and model-call spans identify the selected model. Model availability is determined by the actual OpenAI call; no list request or fallback generation is made.

## HTTP surface

| Method | Path | Request / response |
| --- | --- | --- |
| GET | /api/models | `{provider, defaultModel, models}`; curated OpenAI choices |
| GET | /api/health | `{status: "ok", database: "connected"}` |
| POST | /api/snippets | `{title, language, code}` -> 201 Snippet |
| GET | /api/snippets | Optional `language`, `reviewStatus` -> `{snippets, languages}` |
| GET | /api/snippets/:id | `{snippet, latestReview}` |
| GET | /api/snippets/:id/reviews | `{reviews}` newest first |
| POST | /api/snippets/:id/reviews | `{clientRequestId, model?}` -> 202 new ReviewRun; 200 replay |
| GET | /api/reviews/:id | `{review, findings}` from one snapshot |
| PATCH | /api/findings/:id | `{resolution}` -> updated Finding |
| GET | /api/findings/:id/discussion | Optional `conversationId`, default original -> `{conversationId, conversations, hasActiveReply, turns}` |
| POST | /api/findings/:id/conversations | `{clientRequestId}` -> 201 new conversation; 200 replay |
| POST | /api/findings/:id/discussion | `{message, clientRequestId, conversationId?, model?}` -> 202 new turn; 200 replay |
| POST | /api/discussion-turns/:id/retry | `{attempt}` -> 202 turn with incremented attempt |
| GET | /api/quality/catalog | Evaluation sources and saved session progress |
| POST | /api/quality/sessions | `{sourceId, reviewer}` -> create/resume frozen session |
| GET | /api/quality/sessions/:id | Frozen cases/results and latest annotations |
| PUT | /api/quality/sessions/:id/cases/:caseId | `{revision, status, ...assessment}` -> append saved revision |
| GET | /api/quality/sessions/:id/export | Evidence, metadata, latest annotations, full revision history |

Error envelope: `{error: {code, message}}`. Invalid input returns 400; unknown resources 404; active-job, idempotency, retry, or revision conflicts 409; missing provider configuration for new work 503. Unexpected failures return a safe 500 response. Asynchronous model failures live on their review/turn record. Discussion's `hasActiveReply` covers the whole finding; returned turns belong only to the selected conversation.

## Human evaluation annotations

Sessions freeze source dataset/report snapshots and hashes. `(source_id, reviewer)` is unique; reviewer names are labels, not authentication. Annotations record independent assessment, contract clarity, reference verdict/reason, finding judgments/reasons, coverage, and optional notes. Validate membership and indexes against the frozen session, not current files.

Drafts may be partial. Completion requires all judgments and compatible reference/finding reasons (or legacy written evidence); uncertainty is allowed and all prose is optional. Missing fixes require a Not applicable fix score. Failed model calls cannot count as successful coverage. Completion does not promote labels to gold or modify the source dataset.

Writes compare the supplied revision with the latest saved revision (initially 0), then append in one transaction. Stale writes return 409. A save callback belongs to its mounted editor/submitted draft and cannot clear a newer browser draft or navigate another editor. Exports read saved annotations and history from one snapshot; unsaved browser drafts are excluded. Annotation operations make no model calls and do not alter product findings.

## Model-call diagnostics

Migration 003 stores diagnostic spans by operation, subject ID, and attempt. These are separate from domain execution state and contain no prompt/source/message bodies. They are best effort, with flat review/discussion operations rather than workflow trees. Fields, logging limitations, and CLI usage are in the [quality guide](quality.md#local-model-call-tracing).
